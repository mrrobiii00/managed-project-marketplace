# راهنمای دمو — مارکت‌پلیس پروژه‌های نرم‌افزاری

> این سند برای ارائه‌ی دانشگاهی تهیه شده است: حساب‌های دمو، نحوه‌ی راه‌اندازی و سناریوی کامل ارائه (۱۷ بخش).

## حساب‌های دمو (Demo Credentials)

> ⚠️ این‌ها فقط اعتبارنامه‌های **دمو/توسعه** هستند — هیچ secret واقعی‌ای در این سند وجود ندارد.

| نقش | ایمیل | رمز عبور |
| --- | --- | --- |
| کارفرما (CLIENT) | `demo.client@example.com` | `Demo12345!` |
| متخصص فرانت‌اند (SPECIALIST) | `demo.frontend@example.com` | `Demo12345!` |
| متخصص بک‌اند (SPECIALIST) | `demo.backend@example.com` | `Demo12345!` |
| مدیر سیستم (ADMIN) | `demo.admin@example.com` | `Demo12345!` |

- رمزها فقط با **Argon2id** هش شده و در دیتابیس ذخیره می‌شوند (هیچ plaintext در DB نیست).
- شناسه‌های ثابت دمو: client=`00000000-…-00c1` · frontend=`…00f1` · backend=`…00b1` · admin=`…00a1`.

## داده‌ی دمو (سه پروژه با وضعیت‌های مختلف)

| پروژه | وضعیت | تیم | تسک‌ها | ارزیابی |
| --- | --- | --- | --- | --- |
| **الف) طراحی و توسعه فروشگاه اینترنتی** | IN_PROGRESS | فعال — ۲ عضو با امتیاز تطبیق واقعی (۷۷.۵ / ۷۴.۱۷) | ۱ TODO + ۱ IN_PROGRESS + ۱ DONE (نمایش Progress) | — |
| **ب) اپلیکیشن مدیریت تیم ریموت** | MATCHING | — | — | پیشنهادها فعال: متخصص فرانت‌اند **RECOMMENDED (۸۸.۵/۱۰۰، trust ۸۲)** و بک‌اند NEEDS_REVIEW |
| **ج) طراحی وب‌سایت آموزش برنامه‌نویسی** | COMPLETED | تکمیل‌شده — ۲ عضو | ۲ تسک — همه DONE | ۴ ارزیابی واقعی (۵★ و ۴★ در هر دو جهت) |

- همه‌ی وضعیت‌ها/امتیازها از **workflow واقعی بک‌اند** عبور کرده‌اند: `DRAFT → SUBMITTED → (اجرای موتور تطبیق M07) → REVIEW → تیم → IN_PROGRESS → تسک‌ها → COMPLETED → ارزیابی‌ها (M10)`. هیچ امتیازی دستی در دیتابیس نوشته نشده است.
- Reputation متخصصان از همان ratingهای واقعی محاسبه می‌شود (مثال: فرانت‌اند دمو → میانگین ۵، trust ۸۲).

## راه‌اندازی

پیش‌نیاز: Node.js 20+ و PostgreSQL (دیتابیس `marketplace`، کاربر `postgres`/`postgres`).

```bash
# ۱) نصب وابستگی‌ها
npm install && cd frontend && npm install && cd ..

# ۲) دیتابیس (migrations + مهارت‌های پایه)
npx prisma migrate deploy
npm run db:seed            # catalog مهارت‌ها (idempotent)

# ۳) بک‌اند (پورت 4000)
npm run build
node dist/server.js        # یا: npm run dev (با tsx watch)

# ۴) داده‌ی دمو — سرور باید در حال اجرا باشد (idempotent؛ چندبار اجرا امن است)
npm run db:seed:demo

# ۵) فرانت‌اند (پورت 5173)
cd frontend && npm run dev
```

- حذف فقط داده‌های دمو (بدون دست زدن به سایر داده‌ها): `npm run db:seed:demo:clean`
- اجرای مجدد seed دمو: `npm run db:seed:demo` — هیچ duplicate نمی‌سازد.
- اگر با خطای rate-limit ورود مواجه شدید (۳۰ ورود در ۱۵ دقیقه)، چند دقیقه صبر کنید یا سرور را ری‌استارت کنید.

## سناریوی ارائه (۱۷ بخش — کوتاه و قابل اجرا)

جریان کلی: **معرفی ← دید کارفرما (پروژه/تیم/تسک) ← دید متخصص (پیشنهاد/تطبیق/اعتبار) ← دید مدیر (نمای کل سیستم).**
بین بخش‌های ۶ و ۷ و ۱۲ از دکمه‌ی «خروج» در انتهای سایدبار استفاده کنید.

### بخش ۱ — معرفی مسئله
استفاده از فریلنسرها/تیم‌های نرم‌افزاری بدون ابزار: انتخاب متخصص بر اساس حدس، شفافیت نداشتن امتیاز و اعتبار، و بی‌برنامگی اجرا.
این پلتفرم: ثبت نیاز ← تطبیق هوشمند و شفاف ← تشکیل تیم با بازبینی مدیر ← اجرا و تسک‌بندی ← ارزیابی دوطرفه و ساخته‌شدن اعتبار.

### بخش ۲ — ورود کارفرما
`demo.client@example.com` / `Demo12345!` — پس از ورود، هدایت خودکار به داشبورد کارفرما.

### بخش ۳ — داشبورد کارفرما
آمار واقعی: تعداد کل پروژه‌ها، «در حال اجرا»، «در چرخه‌ی بررسی» + فهرست پروژه‌های اخیر با وضعیت هرکدام. CTA «+ ایجاد پروژه» در دسترس است.

### بخش ۴ — پروژه‌ی اصلی
از «پروژه‌های من» پروژه‌ی **«طراحی و توسعه فروشگاه اینترنتی»** (IN_PROGRESS) را باز کنید: شرح، بودجه، مهلت، مهارت‌های موردنیاز (الزامی/اختیاری) و نقش‌های تیم.

### بخش ۵ — تیم
کارت «تیم پروژه»: نام تیم، وضعیت فعال، امتیاز تیم و هر عضو با امتیاز تطبیق واقعی خودش (۷۷.۵ و ۷۴.۱۷) — اعدادی که موتور تطبیق محاسبه و ذخیره کرده است.

### بخش ۶ — تسک‌ها
بخش «کارهای پروژه»: نوار پیشرفت (۱ از ۳ انجام‌شده)، فیلتر وضعیت، و تسک‌ها با اولویت/وضعیت/مسئول/مهلت. تسک DONE دکمه‌ی حذف ندارد — قواعد بک‌اند در UI آینه شده‌اند.

### بخش ۷ — ورود متخصص
خروج از حساب کارفرما و ورود با `demo.frontend@example.com` / `Demo12345!`.

### بخش ۸ — پیشنهادها
داشبورد متخصص: شمارش پیشنهادها و بهترین تطبیق. صفحه‌ی «پروژه‌های پیشنهادی»: کارت **«اپلیکیشن مدیریت تیم ریموت»** با برچسب «پیشنهاد مناسب» (RECOMMENDED)، امتیاز تطبیق ۸۸.۵٪ و اعتبار ۸۲٪.

### بخش ۹ — دلیل تطبیق (Match Breakdown)
کارت پیشنهاد را باز کنید: امتیاز کل و Trust برجسته + شش مؤلفه‌ی واقعی موتور (تطابق مهارت، تجربه، پروژه‌های قبلی، امتیاز کاربران، دسترس‌پذیری، بودجه). تأکید: این اعداد فقط از بک‌اند خوانده می‌شوند؛ فرانت چیزی بازمحاسبه نمی‌کند.

### بخش ۱۰ — Workspace متخصص
از دکمه‌ی «ورود به Workspace پروژه» بروید و سپس پروژه‌ی فروشگاه اینترنتی را باز کنید: تیم فقط‌خواندنی از دید متخصص، فهرست کارها و دکمه‌های تغییر وضعیت فقط برای تسک‌های خودِ او.

### بخش ۱۱ — پروفایل و اعتبار
صفحه‌ی «پروفایل»: اطلاعات تخصصی + مهارت‌ها با سطح/سابقه + کارت «اعتبار»: میانگین امتیاز ۵ از ۵، تعداد ارزیابی‌ها، پروژه‌های تکمیل‌شده و **امتیاز اعتماد ۸۲ از ۱۰۰** (محاسبه‌ی واقعی موتور reputation).

### بخش ۱۲ — ورود مدیر
خروج و ورود با `demo.admin@example.com` / `Demo12345!`.

### بخش ۱۳ — داشبورد مدیریت
نمای عملیاتی کل سیستم؛ چهار بخش مستقل با دکمه‌ی «بازخوانی» اختصاصی. همه‌ی اعداد مستقیم از endpointهای مدیریت خوانده می‌شوند.

### بخش ۱۴ — خلاصه‌ی سیستم (Summary)
کاشی‌های شمارش: کاربران (کل/کارفرما/متخصص/مدیر/فعال/غیرفعال)، پروژه‌ها به تفکیک وضعیت، تطبیق‌ها، تیم‌ها و وظایف.

### بخش ۱۵ — پروژه‌های اخیر (Recent Projects)
آخرین پروژه‌های ثبت‌شده با کارفرما، تاریخ، بودجه و وضعیت.

### بخش ۱۶ — نیازمند بررسی (Attention)
پروژه‌های در انتظار تصمیم مدیر (SUBMITTED/REVIEW) — صف کاری واقعی مدیر.

### بخش ۱۷ — خلاصه‌ی تطبیق‌ها (Match Summary)
وضعیت کل تطبیق‌ها: کل / توصیه‌شده / نیازمند بازبینی / ردشده — جمع‌بندی عددی موتور تطبیق.

## نکته‌ها

- اعتبارنامه‌ها فقط در همین سند مستند شده‌اند (برای دمو/توسعه — نه production).
- وضعیت MATCHING پروژه‌ی «ب» عمدی است: پیشنهادها فقط پس از اجرای موتور تطبیق فعال می‌شوند و اجرای موتور، پروژه را از SUBMITTED به MATCHING می‌برد (workflow واقعی).
- برای اجرای production: `NODE_ENV=production node dist/server.js` (خطاهای ۵۰۰ بدون جزئیات فنی) و `cd frontend && npm run build && npm run preview` (پورت ۴۱۷۳).
